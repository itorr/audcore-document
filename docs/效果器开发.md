# 声核效果器开发

声核在 Windows x64 上通过 C ABI 加载 `.fx.audcore`。效果器文件包含 DSP、参数定义，以及需要的编辑器、资源、模型和运行库。宿主负责装载模块、连接音频路由、传递参数、保存工程状态和托管编辑器窗口。模块在声核进程内运行，只加载信任的文件。

## 编译并试用增益样例

下载 [gain.c](../website/dist/fx-dev/gain.c) 和 [audcore_fx.h](../website/dist/fx-dev/audcore_fx.h)，放在同一个目录。在 Visual Studio 2022 的 **x64 Native Tools Command Prompt** 中进入该目录，使用支持 C11 原子的 MSVC 工具集编译。

```bat
cl /nologo /utf-8 /std:c11 /experimental:c11atomics /O2 /MT /LD gain.c /link /OUT:ExampleGain-v1.0.0.fx.audcore
```

用支持本地 FX 安装的声核验证。在 PowerShell 中等待安装命令退出，确认退出码为 0。

```powershell
$fx = (Resolve-Path '.\ExampleGain-v1.0.0.fx.audcore').Path
$audcore = 'C:\Audcore\audcore.exe' # 换成实际 EXE 路径
(Start-Process -FilePath $audcore -ArgumentList "--install-fx `"$fx`"" -Wait -PassThru).ExitCode
```

也可以在已关联 `.fx.audcore` 的 Windows 上打开文件。安装后在通道的效果器菜单选择 **Example Gain**，用通道上的主参数调节增益。默认 100% 保持原电平，50% 将样本振幅减半（约 −6.02 dB），0% 输出静音。保存工程、正常退出并重开后，增益应恢复。样例只有一个主参数，省略独立编辑器和翻译。

## ABI 与版本协商

| C 导出 | 宿主请求的版本 | 返回值 |
| --- | --- | --- |
| `audcore_fx_get_rack(uint32_t version)` | 2 | 静态 `AudcoreFxRack` 回调表，必需 |
| `audcore_fx_get_definition(uint32_t version, uint32_t *size)` | 1 | 模块持有的只读 UTF-8 JSON，必需 |
| `audcore_fx_get_editor(uint32_t version)` | 1 | 静态 `AudcoreFxEditor` 回调表，可省略 |

按 [处理器头文件](../website/dist/fx-dev/audcore_fx.h) 和 [编辑器头文件](../website/dist/fx-dev/audcore_fx_editor.h) 保持原生 C 布局和调用约定。用 C++ 时给入口使用 `extern "C"`，按头文件的导出宏或链接器导出精确的符号名，避免异常跨越 ABI。入口不支持所请求的版本时返回空指针。回调表填写实际 `sizeof` 和对应 ABI 版本。宿主检查版本是否相等、尺寸是否至少容纳该版本的完整表。当前宿主只请求表中列出的版本。

定义入口通过 `size` 返回 JSON 字节数，样例不计结尾 NUL。当前上限为 1 MiB。表中的 `code` 与 JSON 完全一致，`fuid` 使用 32 个十六进制字符表示 128 位类标识，两处值一致。派生自己的效果器时生成新 FUID，并在后续版本保留 FUID、`code` 和已有参数身份。回调表中的 `product_version` 是效果器自身版本，例如 `1.0.0`。ABI 版本、产品版本和状态格式版本各自管理。

## 参数和状态

- 定义最多可声明 4096 个参数。必填字段包括 `code`、`fuid`、`vendor`、`label`、`state`、`primary`、`sidechain`、`parameters`、`visual`、`groups`、`actions`。样例展示了空的可视定义、分组和操作字段。可用 `primary` 指定通道上的主参数 ID。
- `get`、`set` 与编辑器按 `parameters` 中的零基索引传递 0 到 1 的归一化值。每个参数有字符串 `id`、`name`、`label`、`minimum`、`maximum`、`step`、`default`、`units`、`skew` 和 `component`。最小值须小于最大值，步长和 skew 须大于零，默认值须在范围内。宿主先把归一化值转为实际单位，按步长量化，再转回归一化值。线性参数用 `skew: 1`。保留已有 ID 和索引顺序，新参数追加到末尾。插件的初始状态应与定义中的默认值一致。
- 宿主控制线程先调用 `save(instance, NULL, 0)` 查询所需字节数，再提供同样大小的缓冲区。第二次返回实际写入长度，须与查询结果一致。若长度可变，在查询时缓存快照供第二次复制。宿主接受 1 至 1 MiB 的状态。无状态可返回 0。
- `restore` 接收插件原来保存的字节。先验证长度、格式版本与取值，再更新实例。成功返回非零，失败返回 0。状态中记录自己的格式版本，升级时读取仍需兼容的旧格式。工程由宿主封装状态。分享工程时，接收方也需要安装相应效果器。

## 实时处理和可视数据

- `create` 返回实例或空指针。宿主在暂停该实例处理时调用 `prepare` 和 `restore`。每次 `prepare` 按采样率、最大块帧数和主声道数重新准备缓冲区，并用 `latency` 报告当前固定延迟，单位为宿主采样率下的帧。成功返回非零。可用 `tail_seconds` 声明已知的尾音时长。
- `process` 原地处理主输入。同一实例的音频调用串行，实际块长可变化。缓冲区总是 `2 * frames` 个交错的 `float32` 样本。即使 `prepare` 传入单声道，主缓冲仍每帧两槽。读左槽并把单声道结果写回两槽。双声道按 L/R 处理。
- 设置 `sidechain: true` 可接收一组只读的立体声侧链，布局同主缓冲。没有侧链数据时指针为空。每块提供 `tempo`，单位为 BPM。音频指针只在该次调用内有效。
- `process` 只执行有界工作。缓冲区在 `prepare` 中分配。回调中禁止堆分配、锁、等待、文件或网络 I/O、界面通知和系统唤醒。参数读写、保存和可视读取可能与处理并发。可在块起点读取无锁参数快照，需要平滑的参数由 DSP 自行插值。
- `visual_active` 通知订阅状态。`visual` 由一个非音频读取方调用，最多写 `capacity` 个浮点数并返回写入数。当前 Rack 宿主每次最多提供 64 个浮点数。音频端只发布固定大小的原子数据或预分配的无锁快照，忙时允许合并或丢弃。无需可视数据时，两项 Rack 回调仍须提供，可实现为空操作和返回 0。销毁前停止插件自己的工作线程与订阅。

## 可选原生编辑器与翻译

实现 `audcore_fx_get_editor(1)` 后，宿主创建顶层窗口，`create` 接收其 Win32 `HWND`、初始归一化参数数组、客户区像素尺寸、DPI 缩放和编辑回调。回调表的 `width`、`height` 是初始逻辑尺寸，当前接受 64 至 4096。实现全部六项回调。不需要的 `visual` 或 `translate` 可使用空实现。省略编辑器导出时，DSP 和主参数仍可使用。第三方效果器如需专用编辑窗口，由包内的编辑器提供。

编辑器创建、更新、调整尺寸、绘制及销毁均在界面线程执行。宿主通过 `parameter` 同步参数，通过 `visual` 传入快照。编辑器在用户操作时调用 `AudcoreFxEdit(context, kind, index, value)`。通用参数手势使用 `2` 开始、`0` 写入归一化值、`3` 结束。宿主送来的参数更新只更新控件显示。传入的数组和翻译结果需要长期使用时先复制，编辑器销毁后停止使用回调及其上下文。

i18n 可省略。单语言效果器可以把自己的默认文案放在 `label["zh-CN"]`，即使默认文案是英文。效果器缺少该名称时宿主可显示 `code`，参数缺少该标签时显示 `name`。需要翻译时，在 `label` 添加 `en`、`ja`，用可选的 `texts` 为编辑器源文案提供语言映射，例如 `"texts":{"重置":{"en":"Reset","ja":"初期化"}}`。编辑器的 `translate` 接收宿主翻译函数和上下文，宿主切换语言时会重新传入。仅在界面线程查询，找不到译文时会返回原文。插件也可以直接绘制自己的默认文案。

## 打包与本机验证

- 通用交付是一个 Windows x64 PE DLL，后缀为 `.fx.audcore`，命名为 `效果器名-v实际版本号.fx.audcore`。把资源和模型嵌入 PE 或链接到模块中，优先静态链接允许再分发的运行库。本地入口接受最大 160 MiB 的 PE，只复制该文件，依赖搜索使用系统目录。把私有 DLL 并排放置或把普通 ZIP 改名无法交付通用 FX。现有伴奏分离 ZIP 有专用加载协议，通用样例使用 Rack ABI 2。
- 安装时宿主验证并复制文件到当前状态目录的 `extensions/plugin/local`，其中子目录由文件哈希区分。便携版状态目录为程序旁的 `Audcore-data`，安装版默认为 `%LOCALAPPDATA%\AudCore`。测试时用安装入口登记，安装后原文件可移走。若已打开的调音台未显示命令行登记的效果器，可正常重启该测试实例，或用已关联的打开入口即时登记。
- 用 `dumpbin /headers`、`dumpbin /exports` 和 `dumpbin /dependents` 检查 x64 架构、入口和运行库。先单独调用 ABI 测默认值、单声道与双声道、不同块长、参数边界、状态往返和错误版本。再在声核中验证安装、调参、工程重开与真实延迟。若带侧链，分别测试有侧链和空指针。若带编辑器，验证开关窗口、宿主参数同步、DPI 和语言切换，并确认界面阻塞时音频仍处理且回调没有堆分配。

## 当前能力与扩展方向

Rack ABI 2 支持一组原地处理的主输入输出、单声道或双声道主信号、最多一组立体声侧链，以及块级 BPM、归一化参数、状态和可选原生编辑器。

向 VST3 同类能力演进时，可用后续 ABI 或版本化能力接口逐步加入多总线及声道布局协商、带帧偏移的事件与 MIDI、采样级参数自动化，以及更完整的传输状态和能力协商。现有 Rack 回调没有这些数据通道。使用当前 ABI 的效果器以实际获传的缓冲区、BPM 和参数为准。
