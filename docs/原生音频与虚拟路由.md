# 原生音频与虚拟路由

声核保留原厂 ASIO，并提供 WASAPI 共享和独占模式。输入设备与实体输出设备可分别选择；实际采样率、缓冲帧数以设备协商结果为准，显示的缓冲时长不是端到端监听延迟。

Audcore 虚拟声卡需要另行安装能在当前 Windows 安全设置下加载的驱动。当前研发包采用本地测试签名；测试签名不等于 Microsoft 正式签名，也不能只靠接受安装警告在默认 Windows 安全策略下加载。未安装或无法连接时，声核不会把三个端点显示为可用设备。

研发安装需要测试模式实际生效及管理员权限；Secure Boot 开启时必须先由用户在固件设置中处理。当前机器尚未启用测试模式、安装驱动或完成端点音频验证，内存完整性仍保持开启。软件构建和本地验签成功不代表驱动已经能够在本机使用。

驱动可用后，其他程序将播放设备选为 **Audcore In Music**，声核在通道输入中选择同名来源，即可把伴奏送入通道效果链。

声核的“添加路由”可选择 **Audcore REC Vocal** 和 **Audcore REC Mix**。分别为人声通道与混音通道添加所需发送；直播或录音程序在录音设备中选择对应端点。名称用于区分目的地，实际声音由选中的源通道和发送取点决定。

实体耳机或声卡的硬件输出仍作为独立发送并行使用，不经过虚拟声卡，不等待直播程序读取。虚拟连接断开会标记不可用并提示恢复，不影响实体耳返。

第一版虚拟端点固定为 **48 kHz、双声道**。引擎以 44.1 kHz 或 96 kHz 运行时，虚拟路由会暂停并提示改为 48 kHz，实体输入和耳返继续工作。声核不自动修改 Windows 默认播放或录音设备。

本轮已验证协议、图路由、软件编译和界面行为；虚拟驱动真实收发、共享/独占实际监听及热拔插仍需在已签名驱动与测试设备环境验证，尚无端到端延迟实测结论。

2026-09-29 已完成软件构建 **v0.0.426** 的协议、软件测试、真实界面 DOM 与前端内嵌验证。此构建未替换正在运行的声核；研发驱动 **0.1.0.2 / ABI v2** 仍未正式签名或安装，不能据此认为虚拟设备已能在本机使用。
