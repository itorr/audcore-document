# 皮肤开发指引

从 [skin-dev](https://audcore.utae.cn/skin-dev/) 获取 SDK、接口资料和模拟开发工具。[下载声核](https://audcore.utae.cn/download/) · [使用指北](https://audcore.utae.cn/guide/)。

## 从独立项目开始

[皮肤列表](../skins.md) 列出每款独立源码。网页项目使用 HTML、CSS 和 JavaScript，原生项目使用 Windows x64 DLL；版本、接口要求及构建命令以该仓库 manifest.json 和 README 为准。本体仓库只保留公共接口、通用控制器和开发夹具，不再维护成品皮肤副本。

[表格皮肤](https://github.com/audcore/audcore-skin-spreadsheet-mixer) 可作为静态网页的完整参考。派生项目须使用自己的皮肤 ID，并保留原作者和第三方许可证。

1. 在根目录 manifest.json 维护名称、版本、类型、语言、运行要求和构建规则。
2. README 写介绍、截图、安装、开发、限制和反馈地址，附上声核官网、下载、skin-dev 及规范链接。
3. 固定工具链和依赖，按文件清单纳入资源，确保不依赖私有仓库或相邻目录。
4. 用模拟数据验证，再在真实宿主完成窗口与功能验收；模拟、静态检查和编译不能代替实际验收。
5. 准备好后向 skins.md 提交登记 PR，按 [皮肤开发与发布规范](皮肤发布规范.md) 完成人工准入。

## 皮肤与宿主的分工

皮肤负责布局和呈现。音频、设备、通道、效果器、工程、历史及真实状态归宿主。设置、通道和效果器标准菜单使用宿主接口，不复制业务逻辑。

网页通过 SDK 的 window.audcore 订阅快照与增量、提交明确操作。初次订阅获得快照，后续按修订号应用变化；发现遗漏时按协议恢复，不以定时轮询或反复拉取整份状态代替通知。

通道视觉名和颜色由宿主提供：

```js
const displayName = state.channelLabels[String(channel.id)];
const displayColor = channel.displayColor;
```

channelLabels 是按通道 ID 保存的最终视觉名，包含宿主的语言、图标及自定义名称规则。当前接口没有 channel.displayName；channel.name 是工程中的原始名称，可能为空。皮肤不应再维护图标到名称的另一份映射；等待名称时可保留当前显示，不将翻译后的名称写回工程。

displayColor 是只读的 #rrggbb 最终颜色。工程颜色允许为空，皮肤不写入计算后的显示色。输入、输出、效果器及发送标签也优先采用宿主提供的数据。

## 运行和清理

皮肤不直接处理音频或操作宿主私有文件。音频线程不调用界面、通知或绘制；隐藏时停止不需要的电平订阅与动画，关闭时释放订阅、监听器、定时器及原生对象。

像素数据与 Alpha 标记保持一致，裁切与复制保留编码，必要边界只转换一次。控件占位稳定，复用公共组件及可访问语义；使用公共 i18n，英文和日文标签应简短自然。

原生皮肤在宿主进程内运行，须专门审核；正常停止回调并释放资源后再卸载，不能强制卸载仍在执行的代码。

## 构建与交付

静态网页只需 manifest 指定的 Node.js，不需要 npm 安装或 C++ 编译。编译型项目声明编译器、SDK、步骤和输出；本机编译串行、低优先级且限制资源。

网页 .skin.audcore 是 ZIP，原生 .skin.audcore 是 DLL，宿主按内容识别。在声核中打开文件安装，再到皮肤设置选用，不直接运行 DLL。文件名、清单和模块版本应一致，禁止覆盖已发布版本。

源码公开、构建成功和进入官方在线列表是不同状态。官方只发布固定源码和审核通过的精确产物；每日 AI 审查及自动发布的启用状态见发布规范，不把规划当作已上线服务。
